## 3. 可自行開發介面的現況

| 介面／能力 | 目前證據 | E900 判斷 |
|---|---|---|
| Bluetooth 5.4 + Wi-Fi | 多個 OEM 宣稱 | 硬體平台合理，需實機確認 |
| 相機、拍照與本機影片保存 | OEM 產品規格／照片 | 可列入實機驗收 |
| E900 **公開官方 SDK** | 尚未找到直接面向此消費裝置的 SDK | **未知** |
| JieLi 晶片 SDK | [iOS-JL_Bluetooth](https://github.com/Jieli-Tech/iOS-JL_Bluetooth)、[Android-JL_Bluetooth](https://github.com/Jieli-Tech/Android-JL_Bluetooth)、[官方文件](https://doc.zh-jieli.com/) | **晶片商 SDK 存在**；E900 是否啟用 RCSP 需驗證 |
| BLE 控制拍攝 | E09 已有逆向命令 | **E900 尚未實證** |
| Wi-Fi HTTP 下載照片／影片 | E09 逆向文件、E900 OEM 的 Wi-Fi 傳輸宣稱 | E900 協定、存取模式未知 |
| 即時 RTSP 影片串流 | E09 研究中的實機測試 | **E900 不可直接視為具備** |
| iPhone 外部 App 控制 | CoreBluetooth 可自建 | 前提：E900 可被控制、可完成初始化與配對 |

### 晶片 SDK 的限制

JieLi SDK 公開描述了 RCSP、設備設定、音訊與自定義命令等能力；但不能據此宣稱 **JL7018F 的所有商用成品** 都啟用 RCSP 或開放攝影 API。影像 SoC DH98562 的軟韌體仍可能由 OEM 設計為封閉實作。

1. 出貨實物的型號／晶片是否確實是 E900（或 E900 Pro）與 DH98562 + JL7018F？

5. 錄影最大時長、儲存容量、韌體版本與實際機身 NCC 標籤資訊？
